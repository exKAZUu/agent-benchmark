## Customer Summary

- `calc` behaves the same for valid input, but bad input now fails clearly instead of misbehaving: unsupported operators, non-numeric or missing operands, and unknown commands each print a message and exit non-zero.
- `--help` output is unchanged in substance and still documents both commands.
- Nothing to migrate or reconfigure. Existing `hello` and `calc` usage keeps working exactly as before, apart from the corrected greeting text.

## Technical Summary

- `src/cli.ts`: `currentText` changed from `Hello via Bun!` to `Hello, World!`. This one line is the actual bug fix.
- `src/index.ts`: rewritten from yargs to commander. Declares `hello` and `calc` subcommands, restricts the operator with `Argument.choices()`, and parses operands through an `argParser` that raises `InvalidArgumentError` on blank or `NaN` input, replacing the previous unchecked `as number` casts.
- `package.json` / `bun.lock`: drop `yargs@18.0.0` for `commander@15.0.0`, which also removes ten transitive dependencies.
- `tests/e2e.test.ts`: CLI coverage grows from 2 cases to 9, adding fractional division, unsupported operator, non-numeric operand, missing operand, unknown command, no-command usage, and `--help` content. Help text is compared after collapsing whitespace because commander wraps long lines.

## Why

- The greeting was leftover project-template text and is printed directly to users, so it is worth fixing on its own.
- The yargs handler cast `argv` fields to `number` and to the operator union without validating them, so malformed input reached `calculate` unchecked. commander expresses that validation declaratively, letting the parser reject bad input before the handler runs.
